# Commerce and Referral Roadmap

The Event OS should monetize useful intent, not interrupt users with generic advertising.

## Day-1 architecture

Commerce is attached to canonical products, places and events through optional offers.

Examples:
- bike/shoe/helmet purchase destinations;
- accommodation;
- rental car;
- attractions;
- local retail;
- expo vendors;
- commemorative merch.

## Attribution maturity

1. ordinary outbound link;
2. approved provider affiliate/referral link;
3. provider-supported campaign/sub-ID;
4. later server-authorized conversion callbacks.

Never invent affiliate parameters or state that a commission exists before approval by the provider.

## Privacy

No cross-site personal profile is needed for V0. Conversion context can be limited to:
- event ID;
- product ID;
- place ID;
- offer ID;
- app surface.

User identity remains absent unless a later consented account explicitly requires it.

## Disclosure

Commercial relationships must be clearly disclosed. Editorial rankings/coverage should not be silently changed by commission rates.

## Organizer/business value

The platform can report funnel-level value once approved integrations exist:
- offer shown;
- offer opened;
- outbound merchant click;
- provider-reported conversion.

This supports sponsor/brand/event business cases without requiring surveillance-style analytics.
